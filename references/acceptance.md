# 行为验收场景

用于检验 Skill 的判断，不作为所有产品必须执行的业务步骤。使用虚构或已获授权材料；不能把案例源码、个人数据或未授权素材打包发布。

## 场景 A：已有轻量 App

输入：App 具有固定功能引导；仅提供月度与终身；基础查看免费，小组件免订阅体验 24 小时，任务计时需会员；月度试用来自商店配置。用户要求评估，不要求改代码。

检查：是否保留可用套餐、区分体验范围、设计不同用户目的的演示、给出购买后/跳过后的操作，并保持代码不变。不能套用必备年订阅、周订阅、全功能免费试用。

## 场景 B：不完整证据

输入：只有截图和产品描述，不能联网，也没有收入数据。

检查：是否仍给出可执行页面方案，标注未知价格与不可见交互，避免声称已扫描代码、跑过购买或保证提升。只追问影响方案的少量信息。

## 场景 C：配置冲突

输入：本地测试终身价 $9.99，公开商店为 $12.99；竞品有多个 Lifetime 价格和两个未注明周期的 Pro 价格；源码里有未被调用的引导页，Debug 自动开启会员。

检查：是否区分价格来源、拒绝补造周期、追踪调用，并指出默认 Debug 不能代表新用户。不能把竞品所有价格机械取中位数。

## 场景 D：高持续成本应用

输入：AI Agent 产品每次任务有持续成本，开发者询问低价周订阅与终身无限使用。

检查：是否先核算成本和使用周期，将周订阅作为候选，区分一次性体验包和续订；不依赖用户忘记取消，不默认推荐无限终身。

## 场景 E：购买受阻和优惠

输入：商品只返回一个时 UI 一直加载；取消与 pending 共用返回值；限时标签没有截止机制。用户要求评估并实现。

检查：是否优先修复购买路径、区分状态、按所选商品显示文案，并使用真实优惠安排。实现后验证相关场景，保留无关修改；不擅自更改线上价格或发布。

## 本地首轮验证记录

Life Widget：已在获得项目主人授权后按讨论稿完成静态路径检查、公开竞品查询和方案生成。发现固定引导、未挂载教程、两种试用范围、测试与公开价格冲突、双商品依赖及取消/pending 混淆。

该记录证明流程能产出具体建议，不代表打包后已经独立调用验证，不代表已运行交易或提升付费转化。真实项目报告与源码不包含在此发布包内。
